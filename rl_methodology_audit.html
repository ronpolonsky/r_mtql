Executive summary

The central MTQL loss is recognizably an off-policy actor–critic objective and does not, by itself, require behavior-policy log-probabilities or importance sampling. The main mathematical failures are in the data presented to that loss: the online collector shares a mutable environment with evaluation, offline and online rewards use different definitions, lazy online chunk samples omit most of the chunk reward, and House time-limit boundaries are not represented as episode boundaries. In active launch configurations, the attention-entropy dual can also be asked to satisfy an impossible target.

The intended chunked Bellman target is:

yt = Σk=0H−1 γk rt+k + γH mt:t+H Q̄(st+H, π(st+H))

This is implemented correctly for ordinary dataset chunking and lazy offline chunking. It is not implemented correctly for lazy online chunking.

Reward labeling and return computation

Is the terminal reward copied across the last steps?

No, not inside a sampled return. Generic chunking clamps array indices at the episode end but multiplies rewards by a validity mask before summation (utils/datasets.py:116–136). Lazy offline sampling excludes incomplete chunk starts and also applies an explicit validity mask (utils/datasets.py:659–669, 771–789). Therefore, a clamped terminal index does not cause its reward to be added H times.

A terminal reward can appear in the targets for multiple overlapping start states. That is expected: each target is a different Bellman equation. It becomes unintended shaping only if the environment or preprocessing emits a repeated success reward as distinct per-step rewards.

Cabinet success rewards are repeated by the environment, not by batching

The cabinet task increments _success_step_count on every raw-success step and sets reward to +1 whenever raw_success is true (open_cabinet_panda.py:720–755). This is an occupancy/stability reward over distinct physical transitions. It is a valid MDP reward if the intended task is “keep the cabinet open and static,” but it is non-potential reward shaping and is not equivalent to a single terminal success bonus. It changes both the optimum and temporal credit assignment.

Critical issues

Critical 1

Evaluation mutates the environment used by the online collector

m_main.py:180–188 → 305–345 → 411–480

Code path
online_env = eval_env; the collector caches observation, history, and episode state. Evaluation later resets and steps that same object, after which collection resumes from the stale cache.
Failed assumption
A replay tuple must be a transition from one Markov trajectory: (st, at, rt, st+1) must all refer to the same simulator state transition.
Practical effect
The stored observation/history may describe the pre-evaluation simulator while the action is executed in a post-evaluation state. Bellman targets then regress on impossible transitions. Evaluation at the initial training step can corrupt the first online transition after warmup.
Correction
Create a dedicated collection environment with independent state and RNG. Never pass it to evaluation or video routines. If sharing cannot be avoided, reset the collector and rebuild all cached history immediately after every evaluation—but a separate instance is the safe minimal fix.
Critical 2

Offline and online replay optimize incompatible reward functions

m_main.py:320–331 · envs/house_env.py:611–623, 1311–1324 · envs/search_cabinet_env.py:180–206 · open_cabinet_panda.py:720–755

Code path
Offline collectors preserve the numeric environment reward. Online collection discards it and stores +1 if success else −1.
Failed assumption
Bellman regression over a replay mixture assumes every sample estimates the same reward function r(s,a,s′), unless task/reward identity is part of the conditioning state.
Practical effect
The critic is asked to fit contradictory returns for the same kinds of state/action transitions. In cabinet, as many as 49 raw-success steps can be labeled +1 offline but −1 online before delayed success activates. In House, online learning removes delivery/count/dense/wrong-pickup semantics.
Correction
Define one training reward relabeler and apply it to both offline files and online transitions. Keep raw_reward, training_reward, and a reward-version identifier so datasets can be migrated and verified.
Critical 3

Lazy online chunks use only rt with a γᴴ bootstrap

utils/datasets.py:924–935 → agents/mtql_transformer.py:30–64; correct offline counterpart at utils/datasets.py:776–789

Code path
Lazy online sampling advances actions and next state by H, but sets rew_out = rewards[idxs]. The critic always bootstraps with discount ** action_chunk_size.
Failed equation
The implementation uses rt + γᴴQ(st+H,·) rather than Σγᵏrt+k + γᴴQ(st+H,·).
Practical effect
Intermediate rewards, including a terminal reward later in the executed chunk, disappear from the target. Learned value scale and credit assignment differ between offline and online samples.
Correction
Use the same tested chunk constructor for generic, lazy-offline, and lazy-online replay. Sum all valid discounted rewards and derive next observation and bootstrap mask from the same boundary.

Scope: this defect is conditional on lazy online replay. Current checked-in online shell commands use --nolazy_dataset, so it is dormant there.

Critical 4

House time-limit resets are not recorded as episode boundaries

envs/house_env.py:1311–1324 → utils/datasets.py:64–66, 443–491

Code path
Collection stops on terminated or truncated, but writes terminals=1 and masks=0 only for terminated. Replay reconstructs episode starts solely from terminals.
Failed assumption
History construction and chunk indexing require every environment reset boundary, even when time-limit transitions are allowed to bootstrap.
Practical effect
Timeout episodes are concatenated with the next reset episode. Histories and action chunks cross unrelated states. If no successful termination occurs, an entire dataset may appear to be one trajectory.
Correction
Store separate episode_end = terminated or truncated and bootstrap_mask fields. Use episode_end for segmentation/clamping and the chosen time-limit convention for bootstrapping. Rebuild affected House datasets.
Critical 5

Configured attention-entropy targets can be mathematically unattainable

agents/mtql_transformer.py:66–93 · utils/networks.py:67–79 · main_mtql_search_two_cams_online_one_step_image_chunk.sh:32 · main_vit_mtql_search_two_cams_online_one_step_image_chunk.sh:30

Code path
Active scripts request entropy targets ((4.5,4.5),(4.0,4.0)). The loss uses a positive exponential temperature; entropy regularization sees a clipped temperature, but the temperature dual loss uses the unclipped value.
Failed constraint
For attention over K keys, H(p) ≤ log K. The reviewed ResNet tokenization has K=39 and maximum ≈3.664; pooled memory-ViT has K=27 and maximum ≈3.296. Targets 4.0 and 4.5 are impossible.
Practical effect
temperature × (H − H*) remains negative, so minimizing it pushes temperature toward infinity and the reported objective toward −∞. Clipping only the entropy-loss path does not bound the dual-loss path.
Correction
Validate each target after final tokenization against log K; preferably target normalized entropy in [0,1]. Parameterize the multiplier with a consistently enforced upper bound or use the same clipped value in both primal and dual terms.

Likely or intent-dependent issues

Likely 1

Cabinet “50 stable steps” is cumulative, not consecutive

open_cabinet_panda.py:720–729

_success_step_count += raw_success.int() never decrements or resets when raw success becomes false. If the intended condition is 50 consecutive stable-open steps, the implementation accepts 50 scattered steps. Reset the count on ~raw_success; otherwise rename/document it as cumulative dwell time.

Likely 2

House wrong-pickup behavior contradicts its stated task definition

envs/house_env.py:74–76, 602–623

The comment specifies immediate termination with reward −3. The environment instead latches wrong_pickup, returns −5 on every subsequent step, and does not terminate. This is not a cosmetic discrepancy: it changes the return by a horizon-dependent amount and encourages ending the episode quickly after an error. Choose one task definition and make termination, reward, collection, and documentation agree.

Likely 3

Offline/online replay ratios differ by storage backend

utils/datasets.py:989–1006 and inherited non-lazy sampling

Lazy replay forces approximately one-third online samples once valid data exist. Non-lazy replay samples uniformly from the combined buffer, so a small online set can contribute almost nothing. Both can be defensible, but they define different training algorithms and critic data distributions. Add an explicit replay-mixture hyperparameter shared by both implementations.

Likely 4

Cabinet resets reuse one seed

envs/search_cabinet_env.py:174–178

reset() reuses self._seed, whose factory default is zero. Unless lower-level randomness advances independently, online episodes can repeatedly start from the same layout. The declared online_reset_seed path is not wired through. Use an episode seed sequence and log seeds for reproducibility.

Likely 5

Chunk length changes actor-loss scale without corresponding normalization

agents/mtql_transformer.py:138–195

Flow and distillation losses are means over action elements, while Q represents an H-step macro return whose magnitude generally grows with H. With normalize_q_loss=False, changing chunk size alters the relative strength of −Q versus imitation even when alpha is unchanged. Retune by horizon/reward scale or normalize Q with a numerically safe denominator such as 1 / (mean(abs(Q)) + ε).

Likely 6

Target critic update is one optimizer step behind

agents/mtql_transformer.py:229–244

target_update(new_network, ...) writes into the new state but reads online critic parameters from self.network.params, not new_network.params. The target is therefore Polyak-updated from the pre-gradient critic. This is inherited from the reference snapshot and is usually a minor one-step lag, not a validity failure. Read from network.params if the intended order is optimizer step then target update.

Offline-to-online policy and probability audit

Offline cabinet trajectories come from a scripted/noisy expert; House data come from ObsExpertAgent; online transitions come from the current actor at collection time. Actions are stored, but behavior log-probabilities are not.

No importance sampling is required for the implemented losses. The critic uses off-policy Bellman regression, the behavior-cloning term is supervised flow matching on replay actions, distillation uses a frozen teacher target, and the Q term differentiates through the current reparameterized actor. None is a likelihood-ratio policy-gradient estimator such as PPO. Stale replay actions and absent behavior log-probabilities are therefore not an on-policy violation.

This conclusion would change if the code added a REINFORCE/PPO-style term, interpreted stored action likelihoods as current-policy likelihoods, or used a multi-step off-policy return containing sampled behavior actions without an appropriate correction. The reviewed objective does none of those things. The actual offline-to-online violations are transition corruption, reward mismatch, inconsistent chunk targets, and broken episode boundaries.

Also, passing temperature=0 does not make action sampling deterministic in the reviewed sampling methods: Gaussian noise is still drawn and the argument does not scale it. This is misleading API behavior, though not an RL objective error.

Complete loss and gradient-path audit

The active transformer agent forms one joint scalar:

L = LQ + Lattention + Ltemperature + Lflow + αLdistill − E[Q(s, π1-step(s))]
TermCoefficient / reductionGradient pathAssessment
Critic MSE Unit coefficient; mean over batch and critic ensemble Current critic only. Target actor/critic calls use stored parameters, not grad_params. Detached target is coherent; correctness depends on replay target construction.
Attention entropy −stopgrad(clipped_temperature) × entropy, global mean Critic attention weights, not temperature Sign is consistent with maximizing entropy, but impossible targets destabilize its dual.
Temperature dual temperature × stopgrad(entropy − target), global mean Positive temperature parameter only Unbounded when target exceeds maximum entropy; inconsistent clipped/unclipped usage.
Flow matching Unit coefficient; MSE mean over batch, horizon, action dimensions Multi-step behavior-cloning flow actor Direction is reversed relative to TQL but sampling integration is reversed consistently.
Distillation alpha; MSE mean over all action elements One-step actor; target flow output is detached because it is evaluated with stored parameters Coherent teacher/student path. Scale is horizon-sensitive.
Actor Q Unit coefficient; negative mean across ensemble and batch Gradient flows through one-step actor actions while critic parameters are frozen Correct deterministic/reparameterized policy gradient structure.

Parameter grouping makes the summed loss workable: actor-only terms update actor modules, critic terms update critic modules, and the temperature term updates its parameter module. The target network and teacher outputs are effectively detached because their calls use stored parameters rather than the differentiable grad_params. The critic call in the actor Q term similarly freezes critic weights while retaining the derivative with respect to its action input. No erroneous actor-through-target or critic-through-teacher gradient was found.

Open questions

  1. Canonical reward: is the intended task reward raw environment reward, one terminal success bonus, 50-step stable-open occupancy, House delivery increments, a remaining-object cost, or universal ±1 survival/success?
  2. Timeout semantics: should value targets bootstrap at a time limit? Regardless of that choice, timeouts must remain replay/history boundaries.
  3. Cabinet stability: must the 50 successful steps be consecutive or merely cumulative?
  4. Wrong pickup: should it terminate immediately for −3 or latch a persistent −5 reward?
  5. Missing collector: collect_cabinet_dataset.py:27–33 imports cabinet_dataset_collector, which is absent from the repository. The final implementation of DataCollector.end_episode and build_episode_dataset therefore could not be audited.
  6. Stored data: no cabinet NPZ episode data are checked in, so actual arrays could not be inspected for terminal-reward padding, masks, or boundary encoding beyond what the visible writer/loader code implies.

Recommended fixes, in order

  1. Separate online collection and evaluation environments. Treat this as a data-integrity fix before interpreting any online-training result.
  2. Choose and centralize reward semantics. Relabel both offline and online samples with the same versioned function; preserve raw rewards for migration and debugging.
  3. Unify chunk construction. One implementation should jointly compute action indices, discounted reward, t+H state, episode boundary, and bootstrap mask for every backend.
  4. Split boundary from bootstrapping. Add episode_end and bootstrap_mask; rebuild House datasets so no history crosses truncations.
  5. Constrain attention entropy correctly. Validate target ≤ log K after tokenization and bound the dual consistently.
  6. Resolve task-definition discrepancies. Decide whether cabinet success is consecutive and whether wrong pickup terminates; align code, documentation, and online relabeling.
  7. Make replay ratio and reset seeds explicit. Use one offline/online sampling parameter across storage backends and advance/log environment seeds by episode.
  8. Add invariants before retraining. Test transition state consistency, H-step reward arithmetic, t+H next state, terminal/truncation clamping, offline/online reward parity, and cached observation agreement with simulator state.
